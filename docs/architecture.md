# Agent 架构

## 核心链路

```text
文件或文本
  -> 文档解析
  -> 任务路由
  -> 专用工作流
  -> 本地规则和可选模型分析
  -> 结构化结果
  -> Markdown、JSON、CSV 导出
```

## 模块

| 模块 | 职责 |
| --- | --- |
| `models.py` | 任务、结果、发现和输出对象 |
| `router.py` | 根据文本和文件名识别任务 |
| `providers/` | 模型调用抽象、Mock 和第三方在线服务适配 |
| `parsers.py` | TXT、DOCX、PDF 和图片解析 |
| `workflows/` | 四类业务的独立规则和提示词 |
| `artifacts.py` | Markdown、JSON 和 CSV 生成 |
| `agent.py` | 任务编排、输出写入和结果组合 |
| `evals.py` | JSONL 离线评测 |
| `sample_evals.py` | 样本清单校验、证据分层、批量评测和报告生成 |
| `cli.py` | 命令行交互 |
| `web.py` | 本地 HTTP 服务、表单上传、静态资源、结果下载 |
| `web_static/` | 无框架前端工作台 |

## 设计决策

### 单 Agent 加工作流

第一版只有一个入口 Agent，不建立多 Agent 对话系统。任务路由后直接进入确定性工作流，降低成本和失败面。

### 本地规则优先

每个工作流在没有模型时也能生成结构化结果。模型失败或未配置时，Agent 会给出明确提示并继续运行。

### 事实约束

简历和申请书禁止补造事实。合同不生成法律结论，票据金额由程序计算。

### Provider 解耦

工作流依赖 `ModelProvider` 接口，不直接依赖具体模型 SDK。后续可以接入其他模型服务。
